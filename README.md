# ДЗ 22. Домашнее задание «Паттерны проектирования»

Новый независимый проект на PHP 8.1+. Реализованы пять задач из учебных
примеров курса. Исходные заготовки преподавателя к сообщению не приложены,
поэтому постановки восстановлены по примерам тем 21–22 и сформулированы ниже.

## Реализованные задачи

### 1. Шаблонный метод

**Задача:** генерация контракта и отчёта должна иметь общий алгоритм: создать
заголовок, обработать шаблон, объединить части документа. Различаются только
заголовок и подстановка данных.

`AbstractDocumentGenerator::generate()` фиксирует скелет алгоритма, а
`ContractGenerator` и `ReportGenerator` переопределяют отдельные шаги.

### 2. Стратегия

**Задача:** стоимость документов рассчитывается либо по числу всех слов, либо
по числу слов длиннее трёх символов. Условные проверки режима внутри сервиса
не допускаются.

`DocumentPricingService` зависит от `PricingStrategy`; алгоритм можно заменить
через конструктор без изменения сервиса.

### 3. Декоратор

**Задача:** к получению заголовка документа независимо подключаются
нормализация регистра и логирование. Наследование всех комбинаций поведения
не используется.

Декораторы реализуют тот же `Document` и могут вкладываться друг в друга.

### 4. Прокси

**Задача:** заголовок документа доступен сразу, а дорогая загрузка отзывов
выполняется только при первом обращении и затем кешируется.

`LazyReviewsDocumentProxy` имеет тот же контракт `ReviewableDocument`, что и
обычный документ, и контролирует обращение к `ReviewsLoader`.

### 5. Цепочка обязанностей

**Задача:** HTTP-запрос последовательно проходит проверки аутентификации,
спам-листа IP и чёрного списка пользователей. Порядок проверок можно менять,
не изменяя сами обработчики.

Каждый наследник `AbstractRequestHandler` выполняет одну проверку и передаёт
запрос следующему звену.

## Почему решение соответствует критериям

- **DRY:** общий код генерации и передачи запроса находится в базовых классах.
- **KISS:** каждый пример решает одну небольшую задачу, без фреймворков и БД.
- **SRP:** класс имеет одну причину для изменения.
- **OCP:** новые стратегии, декораторы и обработчики добавляются новыми классами.
- **LSP:** реализации взаимозаменяемы через заявленные контракты.
- **ISP:** интерфейсы содержат только операции, нужные клиентам.
- **DIP:** сервисы зависят от `PricingStrategy`, `Logger` и `ReviewsLoader`, а не
  от конкретной инфраструктуры.

## Запуск

```bash
composer install
composer test
composer demo
```

В окружении XAMPP:

```powershell
composer install
C:\xampp\php\php.exe tests\run.php
C:\xampp\php\php.exe bin\demo.php
```

Тесты не используют сеть, файловую систему или базу данных.
